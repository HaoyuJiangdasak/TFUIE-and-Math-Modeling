## 第 9 页｜任务友好型增强的三个难点

第一，增强器可能在一种水域数据上训练，却被用于完全不同的任务数据，水质、照明和目标都会改变特征分布。第二，增强不只是改变颜色；去噪、平滑或局部修复可能同时损失有用细节。第三，如果增强只以人眼好看为目标，它不知道哪些图像特征真正影响分割。作者分别用解耦表示、语义对比和任务指导来应对。这里是设计动机，并不意味着每个模块只影响一个因素；后面的消融用受控比较检验它们的增量作用。


依据：PDF p.2–3，引言与贡献

## 第 11 页｜TFUIE 整体训练框架

从左到右读图。上方水下图 X 的内容特征进入增强生成器，得到增强图。下方把 X 的失真特征与陆地图 Y 的内容特征结合，生成合成水下图。两张结果又送回相应网络，分别重建原来的 X 和 Y。框架中两个额外约束是：SACM 保持同一场景的语义内容相近；DTGB 用语义分割从特征和图像两个层次指导增强。图例中蓝色编码器对应内容，橙色对应失真。先理解增强和合成的目的，随后再看各模块公式。测试增强的主路径只需水下输入、内容编码器和增强生成器，训练图里的陆地图和真值标签不是每次增强都需要。


依据：PDF p.5 Fig.2；§III-A


## 第 12 页｜内容与失真解耦：正向交叉转换

解耦可以理解为把“场景中有什么”与“水下环境让它看起来怎样”分开建模。水下内容编码器取 X 的内容，增强生成器用它产生增强图 YX。合成路径用水下失真编码器取 X 的退化表示，再与陆地图 Y 的内容表示相加，生成内容来自 Y、具有水下外观的 XY。这不是把鱼变成陆地房屋，也不是使用 Y 作为鱼图的像素真值。图中失真特征是网络表示，不等同于准确测量的透射率或深度。论文使用三个编码器与两个生成器，各自权重独立。


依据：PDF p.4–5 §III-B、Eq.(1–2)、Fig.2 局部


## 第 13 页｜循环重建：转换后仍要保留原场景

如果模型只把图像的外观改得像另一个域，可能忽略原来的场景。循环重建要求变换后仍能回到原内容：合成水下图 XY 增强后应重建陆地图 Y；增强图 YX 的内容与合成图 XY 的失真组合，应重建水下图 X。损失使用重建与原图的 L1 差异。这是训练上的约束，不是数学上保证严格双射或无损可逆。原文把它称为 forward 和 backward cross translation，三编码器和两生成器之间不共享权重。


依据：PDF p.5 Eq.(3–4)；p.7 Eq.(5)


## 第 14 页｜网络结构：密集连接与多尺度融合

论文以 U-Net 编码器—解码器结构为基础，用 Dense Block 替换普通卷积，并通过四次下采样获得四个尺度的特征。增强路径有水下内容编码器；合成路径还需要水下失真编码器和陆地内容编码器。结构相同只表示这些网络采用同一种设计，不表示权重共享。图中的拼接符号与加法符号也要区分：失真与陆地图内容的公式采用相加融合，而网络内部某些连接采用拼接。Dense Block 让前面产生的特征能够继续被后面的层使用；多尺度融合同时利用局部细节和较大范围的上下文。正文没有完整报告参数量或推理速度，因此不能由结构图断言它轻量或实时。


依据：PDF p.5–6 Fig.3、§III-B


## 第 15 页｜SACM：同内容拉近，不同内容推远

SACM 的特征提取器 G 分别处理原水下图、陆地图、增强图和合成图，输出与输入同分辨率的语义感知特征。增强三元组中，增强图是锚点，原水下图是正样本，因为它们应当是同一场景；陆地图是负样本，因为其场景内容不同。合成三元组则相反：合成图的内容来自陆地图，所以陆地图是正样本。损失是同内容距离与异内容距离的比值，希望前者小、后者大。这个设计帮助模型在去除失真时保留鱼的轮廓等内容，而不是让图像语义变成不相关的陆地场景。这里用的是本文自己的特征提取器，不应写成 VGG19 感知损失；公开仓库还存在其他 VGG 训练依赖，需分开看。


依据：PDF p.6 Fig.4、§III-C；p.7 Eq.(8)


## 第 16 页｜DTGB：特征与图像两层语义指导

这两个分支是两个监督位置，不是同时训练两种不同任务。特征支路把水下内容编码器的多尺度特征直接交给分割解码器，要求内容表示能够预测语义 mask。图像支路先生成增强图，再交给 U-Net 分割网络，要求最终 RGB 图同样保留可分割的信息。两支路都与水下输入对应的语义标签计算交叉熵。本文训练指导只用分割，而检测和显著性检测是在实验阶段检查跨任务效果。原文式 9 第二项印成 Nseg(XY)，与本节文字和图 5 所说的增强图 YX 不一致；本页按明确的图像级增强路径解释，不截取容易误读的式 9。复现时应结合代码确认这个符号疑点。


依据：PDF p.6 Fig.5、§III-D；p.7 Eq.(9)


## 第 17 页｜五种损失与训练目标

总损失包括五项，权重依次为 10、5、1、5、0.2。循环一致性对应两幅原图重建；恒等映射减少对清晰输入不必要的改变；对抗约束负责合成水下图的域真实性；语义对比负责场景内容保留；任务损失将语义分割信号传给增强网络。对抗的具体生成器与判别器交替优化应按代码实现核对，不能仅凭原文式 7 的真假判别表达式推断所有更新方向。各损失尺度不同，权重大小也不直接表示模块贡献。训练是联合优化，并没有本文未报告的独立检测模块预训练过程。


依据：PDF p.7 Eq.(5–10)；§III-E

## 第 20 页｜语义分割：两种网络的平均指标提升

mIoU 先为每类计算预测区域与真实区域的交并比，再在八类上平均。mPA 是按类别平均的像素准确率。表中 TFUIE 在两种网络的 mIoU 和 mPA 都最高。DeepLabv3+ 的 mIoU 从 70.6 到 73.4，提升 2.8 个百分点；U-Net 从 72.2 到 74.8，提升 2.6 个百分点。与其他增强方法相比，DeepLabv3+ 次优 mIoU 是 AAC 72.0，U-Net 次优是 Water-Net 73.2。但不能说所有类别都第一：例如 DeepLabv3+ 上植物类 TFUIE 44.3 低于 Raw 45.5，U-Net 上潜水员 85.4 低于 Raw 88.4。平均改善和局部类别回退需要同时理解。本表只展示聚合指标，完整类别表在论文中。

## 第 22 页｜目标检测：四种检测器的 mAP 比较

mAP 综合衡量各类别检测的精确率与召回率表现，检测框与标注的匹配还受 IoU 阈值影响。原文将指标标作 mAP@0.5:0.95，表内以百分制显示；复现要核对具体评价代码，不能自动换成 AP50。四种检测器涵盖单阶段 RetinaNet、SSD，两阶段 Faster R-CNN，以及水下检测器 FERNet。TFUIE 对应 77.4、65.0、68.1、71.8，对 Raw 的绝对增量是 4.6、5.7、3.8、1.6 个百分点。并非所有其他方法都低于 Raw：TACL 在 FERNet 上 70.4 高于 Raw 70.2，在 RetinaNet 上与 Raw 持平。因此严谨结论是“多数其他方法没有稳定提升”，而非“增强必然使检测下降”。训练指导没有用检测损失，这些结果说明分割指导的增强在所测试检测器上也有收益。

## 第 24 页｜显著性检测：两个数据集的四项指标

显著性检测回答“哪里是突出目标”，通常不需要给每个突出区域一个语义类别。本文用 U2NET。F-measure 综合精确率与召回率，S-measure 衡量结构一致性，E-measure 衡量预测与标注的综合对齐程度，MAE 是像素级平均绝对误差。F、S、E 表内用百分制，MAE 用 0 到 1 的小数，因此提升 3.4 应说百分点，MAE 降低 0.008 应说绝对差，不能混用单位。这里只选 Raw、TACL 和 TFUIE 以保证字大；在包含八种对比增强的完整 Table IV 中，TFUIE 两个数据集四项都最好。TACL 检测指标接近原始图，却在 UFO-120 的 F 指标下降，说明不同任务的收益不一定一致。


依据：PDF p.10 Table IV；展示 Raw、TACL、TFUIE 三种设置

## 第 27 页｜5. 我的思考

## 第 28 页｜主要贡献与可借鉴的设计

三个贡献可以分别作为设计经验。解耦是关于表示的经验：模型不必把内容和失真混在一起学习。语义对比是关于约束的经验：来自同一场景的增强前后图，可以在语义特征上保持相近，即使外观变了。双层指导是关于训练目标的经验：既要求内容特征可被识别，也要求最后生成的图像可被识别。实验说明语义分割指导在所测检测和显著性任务上也有收益，但不能据此保证任何新任务都同样有效。对自己的研究来说，可以先选定要服务的任务，再决定增强模型用什么监督、结果用什么协议评估。

本文不使用水下图与清晰参考图的配对监督，但训练指导分支使用 **SUIM 的像素级语义标注**。没有 SUIM mask 就无法忠实计算两支路的 CE 任务损失。不要将本文描述成“整个训练完全不需要标签”。

### epoch 和 iteration

论文明确报告 **200 个 epoch（训练轮）**。若两个域各 1634 幅、batch=1、按公开 loader 的 `max(A_size,B_size)` 计长且不截断，一个 epoch 约有 1634 次 batch 更新，总计约 **326,800 次 batch 更新**。这是依据假设的换算，不是论文报告的 iteration 数；实际采样列表或裁剪生成策略改变时会变。

4. **先验证小批量再训练**：在自己的副本中检查一批输入维度、类别值、5项loss是否finite、每条梯度路线是否进入目标模块；然后按200epoch执行；保存配置、日志、权重和每个epoch耗时。此为建议，尚未执行。
5. **只保留增强链推理**：原水下图 → ECU内容编码器 → Genh增强生成器；论文训练所需失真编码器、合成生成器、SACM/DTGB/判别器不必加入最终单图增强链。
6. **复核三个任务与消融**：SUIM分割→ChinaMM检测→UFO-120/USOD10K显著性；对照原图及相同下游训练条件。A=基线，B=A+DR，C=B+DTGB，D=B+SACM，最后全模型；记录每项指标的口径。

### 仅作参数对齐示意的训练命令

下述命令**不是已验证可运行方案**；它仅表达论文超参数如何传给公开入口，必须先处理第4节代码阻点、数据与缺权重：

```powershell
python train.py --dataroot ./datasets/TFUIE --name tfuie_paper --model cycle_gan --gpu_ids 0 --batch_size 1 --n_epochs 100 --n_epochs_decay 100 --lr 0.0002 --lr_policy linear --display_id -1
```

`lr_policy linear` 是仓库实现选择，正文只说后100epoch衰减至0；需在复现记录中说明。`--display_id -1` 是关闭本地visdom显示的便利设置，非论文算法参数。训练命令中的load/crop不额外填，因为当前loader对应处理被注释，仅传参数不能完成论文裁剪。

README 原测试命令只作为出处保留，不在PPT宣称“直接运行即可复现”。测试应先修复单向增强模型注册、checkpoint目录、dataloader需求与完整测试数量。
